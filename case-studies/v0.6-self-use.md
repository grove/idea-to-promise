# v0.6 self-use case study

**Maintainer-authored real project use. Not an independent evaluation, user study,
or proof that ITP improves decisions generally.**

## Need

After v0.5, the strongest documented gap was no independent live-agent evidence.
The project also had a one-way ITP -> P2P handoff and no explicit post-delivery
outcome record. The goal for this change was to improve evidence and feedback
without adding more mandatory discovery stages.

## Options considered

- Add more discovery methodology.
- Add an autonomous controller.
- Strengthen evidence/feedback while keeping the existing umbrella workflow.

The third path was selected because the first two would increase ceremony before
the current behavior has been independently validated.

## Important evidence and limits

Repository validation explicitly said live-agent evaluation was still unassessed.
The existing evaluation harness, exact approval receipts, resume/revisit behavior,
and P2P handoff already provided a foundation for a feedback-oriented release.

This case is self-referential and authored during implementation. It is useful as
a traceable project example, not as independent evidence about ITP quality.

## Decision

Keep the seven discovery stages plus setup. Add modes to `/discover` for amendment
and post-delivery outcome review, team decision ownership, non-numeric decision
posture, stronger untrusted-source rules, deterministic work-item status, and
friction observability in evaluations.

Do not claim a live-agent pass without an actual configured adapter and retained
review.

## Expected learning

v0.6 should make it easier to answer:

- Why was this decision made and who owned it?
- Did P2P find a delivery issue or a promise issue?
- Did the delivered behavior actually improve the intended outcome?
- How much conversational/artifact friction did a trial create?
- What remains unassessed?

The next evidence step remains an actual live-host run of the checked-in suite.
