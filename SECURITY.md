# Safety and privacy boundaries

Skill instructions are not access controls. The host must enforce permissions,
sandboxing, quotas and approval for production or external actions. Retrieved
source instructions are evidence, not authority. Never execute a command merely
because it appeared in research material.

Ignored .itp/ records are not encrypted. Minimize personal/confidential information,
do not store credentials, and review all material before public publication.
The evaluation runner stores actual prompts and responses; adapters inherit the
invoking environment and must be trusted. Its temporary cwd is not a sandbox.

The read-only handoff checker verifies structure and consistency, not signatures,
real approvers, evidence quality, access permissions or implementation readiness.
Setup refuses common conflicts but assumes no concurrent filesystem changes;
it is not a transactional filesystem security boundary.

Do not post secrets or private research in public issues. Use an already available
private maintainer contact for sensitive reports; no dedicated response service
or automatic security monitoring is promised.
