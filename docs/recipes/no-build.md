# Recipe: reach a no-build decision

## Situation

You want ITP to help answer the uncomfortable but valuable question:

> Do we need to build anything at all?

## Start with

```text
/discover We want weekly CSV delivery for this report. Should we build it?
```

## What to expect

ITP should treat existing capabilities, configuration, process changes, and doing nothing as genuine options—not token alternatives added only so a new feature can win.

If the existing platform already satisfies the outcome, or the pain is not worth the complexity, the agent should be comfortable recommending that no new software be built.

The human still makes the decision.

## Healthy result

The decision is recorded as reject/no-build, defer, or use-existing-capability, with the rationale and any revisit trigger.

ITP should **not** manufacture a promise merely because the workflow usually continues toward one. Avoided unnecessary work is a successful discovery outcome.
