# Recipe: revisit an approved promise

## Situation

An approved promise already exists, but something meaningful has changed: user behavior, constraints, evidence, business context, or another revisit trigger.

## Start with

```text
/discover revisit specs/<slug>.md
```

## What to expect

ITP should begin with the current approved promise and ask what changed. It should preserve the existing source and approval while any replacement is still only being discussed.

The purpose is not to reopen everything automatically. If the old decision still makes sense, the result may simply be “keep the current promise.”

If the decision changes materially, ITP should preserve the old history, record the new human choice, shape a new promise revision, and require exact approval again.

## Healthy result

You can explain both:

> Why did we make the old promise?

and:

> What new evidence justified changing—or keeping—it?

Nothing is silently rewritten.
