# Idea to Promise documentation

Welcome. If you are new to ITP, you do not need to understand the protocol, record formats, hashes, or evaluation harness before using it. Start with the outcome you want help thinking through, and let `/discover` guide the conversation.

The documentation is organized so you can go deeper only when you need to.

## New here?

Start with **[Getting Started](getting-started.md)**. It is a short, end-to-end walkthrough designed to give you one successful experience before introducing the machinery underneath.

Then read **[The mental model](mental-model.md)** if you want to understand why ITP separates an idea, evidence, a human decision, an approved promise, and later proof.

If you just need a reminder of the commands, keep **[the cheat sheet](cheatsheet.md)** nearby.

## I know what situation I am in

The **[recipe book](recipes/README.md)** gives short guides for common situations. Each recipe starts from a real question, shows the command to use, explains what ITP should do, and tells you what a healthy result looks like.

You will find recipes for new features, technical choices, experiment-first decisions, no-build outcomes, continuing previous work, revisiting an approved promise, handling P2P feedback, and reviewing whether delivered work actually helped.

## I want the exact rules

The **[reference index](reference/README.md)** points to the deeper protocol and artifact documentation. This is where you should go if you are integrating ITP into tooling, reviewing approval semantics, understanding the P2P boundary, evaluating agent behavior, or contributing to the project itself.

The important onboarding principle is simple: **use the conversation first; learn the internal machinery when it becomes useful.**
