# Frame the problem

Clarify the question before selecting a solution or approving a promise.

## Work record

When operating in a writable project, derive a short stable slug and save the
record to .itp/work/<slug>/frame.md. Preserve an existing work item and human
edits. Local saving grants no commit, push, tracker, or publication authority.

For an informal conversation without a writable project, return the same record
inline rather than inventing persistence.

## Establish the frame

Read the idea and relevant supplied context. State the current problem or
opportunity, audience, desired observable change, status-quo consequence,
constraints, established non-goals, decision criteria, assumptions, material
unknowns, and research bounds.

Separate the underlying need from the first proposed solution. Attribute supplied
reports rather than turning them into observations. Mark inferred context as an
assumption.

Ask only questions whose answers can materially change the next step. If missing
information is not load-bearing, continue with explicit assumptions.

## Output

Use headings: Problem or opportunity; Audience; Intended outcome; Context and
constraints; Decision criteria; Assumptions; Material unknowns; Research bounds;
Next action.

Save and reread the record before reporting a durable handoff.

Do not choose a solution, implement product code, publish externally, create a P2P
acceptance contract, or claim that a framed outcome is already an agreed promise.

End with Next steps: and numbered applicable options, normally /brainstorm
.itp/work/<slug>/frame.md and focused research when an unknown is already clearly
decision-critical.
