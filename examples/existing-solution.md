# The existing system already does it

> Fictional teaching example. The dialogue and source notes are authored fixtures, not live-agent output, customer research, or real approval.

## Seed, frame and options

**User:** “We need to build a scheduled CSV export.”

O1 is obtaining the same report every Monday without manual clicking. S1, the
fictional supplied platform manual, says the current plan already includes weekly
CSV scheduling. S2, a supplied configuration snapshot, shows that this feature is
enabled for the relevant team. These are fixture inputs, not externally verified
product claims.

A1 is a new scheduled job; A2 is using the existing scheduler; A3 is manual export.
C1 links the built-in capability to the need. The remaining question is whether
its recipient and report scope match, not which queue product to buy.

## Focused research and choice

The supplied fixture configuration supports the required report and recipient.
There is no evidence that a second scheduler adds value.

**Agent:** “The existing scheduler appears to cover the stated need. Building a
second one introduces maintenance without a demonstrated benefit. Should we stop
the new-build idea and use the existing capability?”

**User:** “Yes. No new code. I will configure the existing schedule.”

D1 records reject/new-build, that user statement, relevant S/C references, and a
revisit trigger: the built-in scheduler demonstrably cannot handle the required
report or delivery constraints. The agent does not configure the live system
without separate authority.

## End

moving. A short same-context check is sufficient; no independent review is claimed.
